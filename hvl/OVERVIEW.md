# hvl/ — Testbench Source Overview

Hardware verification sources. Split into `common/` (shared between all simulators) and per-simulator directories (`vcs/`, `verilator/`).

---

## common/

### `top_tb.svh` — Shared Testbench Body

Included by both `vcs/top_tb.sv` and `verilator/top_tb.sv`. Instantiates:
- `mem_itf_w_mask` — memory bus interface
- `simple_memory_w_mask` — behavioral memory model
- `mon_itf` — RVFI monitor interface
- `monitor` — RVFI monitor controller
- `rv64_core_wrapper dut` — the design under test

Also includes `rvfi_reference.svh` (auto-generated) which wires `dut.monitor_*` ports into the `mon_itf`. The main loop decrements a timeout counter and calls `$finish` when `mon_itf.halt` asserts.

### `monitor.sv` — Commit Monitor

Watches the `mon_itf` for retired instructions each cycle. Detects the halt encoding (`slti x0, x0, -256` = `0xF0002013`) and asserts `mon_itf.halt` to end simulation. Also tracks IPC/cycle counts and triggers FST waveform dumping on ROI markers (`slti x0, x0, 1` = start, `slti x0, x0, 2` = end).

### `rvfimon.v` — RVFI Formal Monitor

Auto-generated by the riscv-formal toolchain:

```bash
cd third_party/riscv-formal/monitor
python3 generate.py -i rv64imac -a -r 0 -c 1 > ../../../hvl/common/rvfimon.v
```

Maintains a shadow register file and checks every RVFI commit against it. Detects incorrect rs1_rdata, rs2_rdata, rd_wdata, memory access values, and PC updates. Calls `$error` and `$fatal` on any mismatch. Covers the full RV64IMAC ISA: all IMC instructions are fully verified; LR.W/D and all AMO read-modify-write instructions (AMOSWAP, AMOADD, AMOXOR, AMOAND, AMOOR, AMOMIN, AMOMAX, AMOMINU, AMOMAXU) are fully verified; SC.W/D have `spec_valid=0` (outcome depends on reservation state).

**Do not hand-edit this file.** To regenerate: first run `python3 gen_amo.py` in `third_party/riscv-formal/insns/` to create the AMO checker modules (they are not included in the pinned riscv-formal submodule), then run the monitor generator above.

### `rvfi_reference.json` — RVFI Signal Mapping

JSON configuration consumed by `bin/rvfi_reference.py` at build time. Maps RVFI monitor port names to `dut.monitor_*` signal names. The build script emits `rvfi_reference.svh` from this file.

### `rvfi_reference.svh` — Generated RVFI Wiring

Auto-generated by `bin/rvfi_reference.py` during `make`. Assigns `dut.monitor_*` ports into the `mon_itf` channels so the RVFI monitor sees the DUT's reported instruction metadata. Do not edit by hand.

### `mem_itf.sv` — Memory Bus Interface

Defines `mem_itf_w_mask` — the parameterized SystemVerilog interface connecting `rv64_core_wrapper` to `simple_memory_w_mask`. Ports: `addr`, `rmask`, `wmask`, `rdata`, `wdata`, `resp`, `error`. 8 bytes wide, 64-bit address.

### `mon_itf.sv` — Monitor Interface

Defines `mon_itf` — the interface carrying per-channel RVFI fields (`valid`, `order`, `inst`, `trap`, `rs1_rdata`, `rs2_rdata`, `rd_wdata`, `pc_rdata`, `pc_wdata`, `mem_addr`, etc.) plus `halt` and `error` control signals.

### `masked_memory.sv` — Behavioral Memory Model

`simple_memory_w_mask`: a byte-masked, parameterizable delay memory (default `DELAY=3` cycles). Loads initial contents from the `.lst` file passed via `+MEMLST_ECE411=`. Stores data in a sparse associative array indexed on `[DWIDTH-1:3]` (64-bit aligned). Handles simultaneous read+write by prioritizing the write.

### `rvfimon.v` — (see above)

### `spike.so` — Spike DPI Shared Library

Pre-compiled Spike ISA simulator shared object used for DPI-based co-simulation (when `ECE411_NO_SPIKE_DPI` is not defined). The build defines `ECE411_NO_SPIKE_DPI` by default; this file is present for completeness.

## vcs/

### `top_tb.sv` — VCS Top-Level Testbench

Wraps `top_tb.svh` with VCS-specific clock generation, reset logic, and `$fsdbDumpvars` waveform setup. Compiled with `make vcs/top_tb`.

## verilator/

### `top_tb.sv` — Verilator Top-Level Testbench

Same structure as the VCS version but uses `$dumpfile`/`$dumpvars` for FST output (via `--trace-fst`). Clock and reset are driven by the C++ harness.

### `verilator_harness.cpp` — Verilator C++ Driver

The `main()` for the Verilator binary. Parses `+TIMEOUT_ECE411`, `+MEMLST_ECE411`, `+CLOCK_PERIOD_PS_ECE411` plusargs, drives the clock, and calls `eval()` each half-cycle. Handles FST trace open/close and graceful exit on `$finish`.
